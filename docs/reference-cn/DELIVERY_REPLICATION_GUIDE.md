# GIS-WORKTABLE-CN 交付复现与换机操作指南

本文档面向测试验收人员、评审专家与异机复现者，提供小型示例数据说明、端到端全流程操作步骤、预期判定标准以及安装失败时的备用方案。

---

## 一、随仓小型合成数据说明

仓库已内置小型、免联网、具备复合几何与属性特征的测试数据：
- **文件路径**：`data/sample_delivery_test.geojson`（以及 `test_data/sample_delivery_test.geojson`）
- **文件大小**：约 1.6 KB
- **数据结构与要素**：
  1. **面要素（Polygon）**：园区重点开发核心区（4 个顶点构成的围合区域，包含名称、面积基准等 10 项业务属性）；
  2. **线要素（LineString）**：园区物流主干道走廊；
  3. **点要素（Point）**：环境监测站关键枢纽。
- **设计初衷**：体积轻量，无需公网下载或申请商业 Token；一次导入即可全面测试图层解析、地图着色、缓冲区分析、属性表展示与成果导出。

## 二、端到端全流程复现操作步骤与预期现象

### 步骤 1：服务启动与主界面就绪
- **操作方式**：
  - 方式 A：双击运行根目录下的 `start.bat`，首次自动检测并下载 Python/依赖，已有可用环境直接启动。首次须联网且项目目录可写；依赖默认源失败后自动尝试清华镜像，Python/uv 下载需能访问官方 GitHub 分发源。失败会保留错误提示，可恢复网络后重试；
  - 方式 B（命令行手动）：
    ```bat
    .venv\Scripts\activate
    python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
    ```
- **预期现象**：
  - 控制台显示 `Uvicorn running on http://127.0.0.1:8010`；
  - 浏览器自动弹出并加载工作台首页，页面中央 Leaflet 2D 地图及右侧控制底栏正常显示，无红屏或崩溃。

### 步骤 2：导入随仓 GeoJSON 示例
- **操作方式**：
  - 点击左侧导航栏的 **「数据」** 面板；
  - 点击 **「上传文件」** 按钮，选择随仓文件 `data/sample_delivery_test.geojson`。
- **预期现象**：
  - 图层面板新增图层条目 `sample_delivery_test.geojson`；
  - 地图视口自动定位至要素区域，清晰渲染 1 个面、1 条线与 1 个点要素。

### 步骤 3：执行 500 米缓冲区空间分析（无需模型密钥）
- **操作方式**：
  - 点击左侧 **「工具」** -> **「空间分析」**；
  - 在分析工具下拉列表中选择 **「缓冲区 (Buffer)」**；
  - 输入图层选择 `sample_delivery_test.geojson`，缓冲距离填 `500`，单位选择 **「米 (meters)」**；
  - 点击 **「执行分析」**。
- **预期现象**：
  - 弹出“分析执行成功”通知；
  - 图层面板新增成果图层 `sample_delivery_test.geojson_缓冲区_...`；
  - 地图上即时渲染出向外膨胀 500 米的半透明缓冲面图层。

### 步骤 4：属性表查看与字段检查
- **操作方式**：
  - 在图层面板中选中缓冲区图层，点击图层工具栏的 **「属性表」** 图标（或右键菜单选择“打开属性表”）。
- **预期现象**：
  - 页面下方平滑展开属性表抽屉；
  - 表格清晰展示 11 列属性字段（保留原业务字段并附加计算指标），共渲染 3 行数据记录。

### 步骤 5：处理历史审查与一键重跑
- **操作方式**：
  - 点击界面右下角的 **「处理历史」** 面板；
  - 找到刚才记录的“缓冲区分析”流水条目，核对执行参数与时间戳；
  - 点击该条目操作栏中的 **「重跑」** 按钮。
- **预期现象**：
  - 历史任务成功重新执行并弹出成功提示，分析管线具备可重复性。

### 步骤 6：成果导出为 Shapefile 压缩包
- **操作方式**：
  - 选中缓冲区成果图层，点击 **「导出」** -> 选择 **「ESRI Shapefile (.zip)」**。
- **预期现象**：
  - 浏览器下载一个形如 `delivery_buffer_export.zip` 的压缩包；
  - 解压该文件，内部完整包含 `.shp`（几何数据）、`.shx`（索引）、`.dbf`（属性表）、`.prj`（WGS-84 投影声明）、`.cpg`（UTF-8 字符集），可在 QGIS 或 ArcGIS 中直接导入无报错。

### 步骤 7：工程保存
- **操作方式**：
  - 点击顶部导航栏 **「工程」** -> **「保存工程」**，输入工程名称（如 `验收测试工程`）并点击保存。
- **预期现象**：
  - 弹出保存成功提示，并返回持久化工程 ID（写入本地 SQLite 数据库）。

### 步骤 8：模拟服务关停与工程重开恢复
- **操作方式**：
  - 关闭浏览器，在终端运行 `stop.bat` 彻底停止后端服务；
  - 重新启动服务（运行 `start.bat`），在浏览器打开工作台；
  - 点击 **「工程」** -> **「打开工程」**，选择刚才保存的工程。
- **预期现象**：
  - 工程加载成功，原始图层与缓冲区分析成果图层全部完整恢复到地图画布与图层列表中。

## 三、环境安装失败常见问题与备用替代方案

若在全新电脑或特殊网络环境部署时遇到安装阻碍，请参考以下成熟替代方案：

### 1. pip 默认官方源连接超时 / 速度极慢
- **原因**：目标机器无法直接稳定访问境外 PyPI 官方源。
- **替代方案**：使用国内清华大学或阿里云高可用镜像源：
  ```bat
  python -m pip install -r backend\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
  ```

### 2. 依赖解析速度慢或出现 Windows 编译轮子缺失
- **原因**：部分科学计算库依赖 C 扩展，若本地环境未安装 Visual C++ 运行库可能编译慢。
- **替代方案**：利用现代极速包管理器 `uv`（自带高并发解析与预编译 wheel 下载）：
  ```bat
  python -m pip install uv
  uv pip install -r backend\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
  ```

### 3. 默认 8010 端口被其他软件占用
- **原因**：`8010` 端口若被本地开发服务占用，启动器为防止覆盖会阻止启动。
- **替代方案**：指定自定义端口环境变量（如 8015）：
  ```bat
  set GIS_PORT=8015
  start.bat
  ```

### 4. 双击 `start.bat` 窗口闪退
- **原因**：缺少 Python 环境变量或当前虚拟环境尚未建立。
- **替代方案**：在命令提示符（CMD）或 PowerShell 中逐行排查：
  ```bat
  python --version           :: 确认 Python >= 3.11
  python -m venv .venv       :: 重建虚拟环境
  .venv\Scripts\activate     :: 激活
  pip install -r backend\requirements.txt
  python -m backend.launcher start --port 8010
  ```

### 5. 全新电脑无 Python 且 GitHub 无法访问
- **关键说明**：`start.bat` 内置依赖镜像源（清华源），但**依赖镜像源仅能解决第三方 Python 库下载，无法解决 Python 解释器本身的下载**（uv 默认从 GitHub Releases 下载 Python 二进制）。
- **解决办法**：
  1. 从国内高速镜像站直接下载 64 位 Python 3.13 安装包：
     - 华为云镜像（推荐）：[Python 3.13.0 amd64](https://mirrors.huaweicloud.com/python/3.13.0/python-3.13.0-amd64.exe)
     - 淘宝/npm 镜像：[Python 3.13.0 amd64](https://registry.npmmirror.com/-/binary/python/3.13.0/python-3.13.0-amd64.exe)
     ★ **安装时务必勾选安装向导底部的【Add python.exe to PATH】！**
  2. 若机器已有其他位置的 Python 3.11-3.13，可在启动前指定：
     ```bat
     set GIS_PYTHON=C:\你的Python路径\python.exe
     start.bat
     ```

### 6. 复制来的失效 `.venv` 或换机迁移
- **自动处理**：`start.bat` 内置环境有效性校验机制。若直接从其他机器复制了带有绝对路径的失效 `.venv`，启动脚本会自动检测到解释器无法运行，将失效环境备份至 `.bootstrap/old-venv-<guid>`，并自动基于当前机器 Python 原地重建纯净 `.venv`。
- **手动处理**：若需手动清理，直接删除根目录下的 `.venv` 和 `.bootstrap` 目录，然后重新双击 `start.bat` 即可从零干净初始化。

### 7. 连续双击防护与优雅关停
- **连续双击保护**：系统已内置 `bootstrap.lock` 与启动互斥锁，连续多次双击 `start.bat` 不会发生端口 10048 冲突，也不会重复打开多个后端窗口；浏览器打开具有防抖机制，不会弹出多个标签页。
- **服务停止**：双击运行根目录下的 `stop.bat`，即可安全退出后台 uvicorn 服务并释放端口。
