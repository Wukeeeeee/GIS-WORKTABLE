# 公开数据获取：首次使用验证记录与任务脚本

记录日期：2026-10-22。目标是验证一条已有能力能否被发现、正确执行和核对，而不是宣布公开 REST 下载已成为产品定位。首页入口使用“公开数据获取”，不再把这项可选功能叫作“首次任务”。

## A. 首要阻碍与证据

首要问题是**从找到入口到正确理解并拿走成果的交接过程**，不是缺少分析算法。

| 观察 | 原始位置或证据 | 强度与边界 |
| --- | --- | --- |
| URL 获取藏在通用连接器内，原“云原生格式”标题也包含 ArcGIS REST；检查结果把几十个字段挤在一个长段里 | `frontend/index.html`、`frontend/js/connector.js`；本轮实际页面检查 | 技术/界面直接证据；不能据此估计多少用户会遇到问题 |
| 四个链接返回 200 不等于四份文件可下载；实际浏览器中的 JSON 清单两次未落盘，数据和 Markdown 报告可落盘 | 浏览器 download 事件、下载目录与本地 HTTP 日志；改为附件响应后四份均已落盘 | 本轮浏览器可复现；未泛化为所有浏览器都有同样问题 |
| 页面重载后点击重跑，保存的 full/CA 查询已执行，但表单仍显示空地址、preview、`1=1` | 重载后的真实界面，`frontend/js/connector.js` 重跑处理器 | 直接行为证据；现已恢复可见条件并锁住重复启动 |
| README 指向的 `.venv` 中，旧 MCP 1.12.4 无法导入 Pydantic 2.14.1 的已移除内部接口；真实 STDIO 又发现启动日志污染协议、首次载入 GIS 库迟滞 | 本轮 `.venv` 测试、真实 SDK 子进程探针 | 本机环境证据；属于可选集成的接入故障，不是用户需求证据 |

相关外部来源（均访问于 2026-10-22）：

- **官方功能**：[QGIS 3.44 ArcGIS REST 接入文档](https://docs.qgis.org/3.44/en/docs/user_manual/managing_data_source/opening_data.html#using-arcgis-rest-servers)已经支持连接、选层、过滤、元数据和上图；文档未标发布日期。不能声称必须用 WorkTable 才能做这些事。
- **维护者说明**：[GeoDataDownloader README](https://github.com/mchaynes/geodatadownloader#how-it-works)明确按对象 ID 分批下载；页面未标发布日期。“有完整下载”本身没有形成差异化。
- **用户反馈及已修复的反证**：[QGIS MCP #52](https://github.com/nkarasiak/qgis-mcp/issues/52)，2026-09-22 提交并关闭：维护者解释，成功运行时丢弃 Processing 警告曾掩盖跳过的几何，v0.15.0 已返回警告。这支持检查包装层反馈的重要性，不证明最新版竞品仍有该问题，也不证明 WorkTable 有真实采用需求。

尚无本轮真人访谈或受试者观察。用户能否独立完成、是否需要这种交付包、是否优于原工作流，均待验证。

## B. 三个候选与取舍

规模为独立开发者的粗略估计，不包含此前已实现的数据获取引擎。

| 候选 | 目标用户与具体任务 | 阻碍、不改的代价与证据 | 规模、风险与决策 |
| --- | --- | --- | --- |
| **公开 REST 地址到可检查的本地成果** | 已有一个公开 REST 链接、准备把指定范围数据交给 QGIS/ArcGIS 同事的分析人员 | 入口、元数据阅读、状态解释、实际下载及复跑条件存在上述直接问题；不改会继续让已有能力难以被正确使用 | 小，约半天至一天；第三方网络和源数据变化不可控。**本轮选中**，先修这些已观察到的问题 |
| MCP 作为主要上手入口 | 本来就在用外部 AI 客户端、希望调用本机 GIS 工具的人 | 配置和实际进程有故障，但目标人群规模和重复任务没有证据；其他 QGIS MCP 已存在 | 中，若含地图回传和客户端支持约数天；维护成本可能超过价值。保留可选接入，修已发现故障，不作为首页主路径 |
| 再加一个分析向导，例如 500 米缓冲区 | 已有合适数据、希望完成固定分析的 GIS 初学者 | 现有工具已覆盖常见缓冲；没有本轮证据指出新算法或新向导是最先卡住的一步 | 中，约一至数天，另需核验单位、投影和输入。暂不做，不能解决当前已观察到的交接问题 |

## C. 本轮实际改动

- 首页以“公开数据获取”提供地址/示例入口和旧数据提醒，README 对应章节标为可选。预览与完整获取的边界在获取面板、结果和指南中解释，首页不再重复长段说明。
- 检查结果优先显示图层、几何、CRS、ID、单次上限、分页能力；字段默认折叠，并说明下一步及检查边界。
- 下载链接使用 `?download=1`，输出路由返回 `Content-Disposition: attachment`；地图读取不带该参数，保持内联读取。
- 重跑恢复保存的可见参数，启动中和执行中锁住重复提交，失败后解锁。
- MCP 配置放 README/专项指南。依赖范围调整为 MCP 1.28.1 至 2.0 之前版本、Uvicorn 0.31.1；本机同步安装了 1.28.1、0.31.1 及其 PyJWT 依赖。日志走 stderr，GIS 库在启动 STDIO 前加载。未迁移框架。

本轮修改文件索引（保留此前已有的工作区改动）：

- 产品界面：`frontend/js/workspace.js`、`frontend/js/connector.js`、`frontend/index.html`、`frontend/css/workspace.css`、`frontend/css/style.css`。
- 服务与依赖：`backend/main.py`、`backend/services/mcp_server.py`、`backend/requirements.txt`。
- 定向测试：`frontend/tests/workspace_dock_state.test.cjs`、`frontend/tests/connector_online_load.test.cjs`、`backend/tests/test_url_vector_jobs.py`、`backend/tests/test_mcp_server.py`。
- 说明及证据：`README.md`、`docs/USER_GUIDE_ARCGIS_URL.md`、`docs/mcp_server.md`、本文及 `docs/validation/` 中的 JSON 核对记录和空白 CSV。

## D. 技术验收与未验证项

[机器可读核对记录](validation/arcgis-first-task-2026-10-22.json)保存了实际下载文件名、大小、哈希和直接源 ID 比对结果。

| 检查 | 结果 |
| --- | --- |
| 非首页预填地址 | 手动输入公开 Esri `USA/MapServer/0`（Cities），过滤 `st = 'CA'`；它仍是演示服务，不是用户自己的业务任务 |
| 预览/完整状态 | 预览 446 条显示“完整性未检查”；完整获取 446/446，明确说明 ID 稳定不证明属性快照一致 |
| 下载和独立读取 | 四个附件均实际落盘；GDAL/GeoPandas 读取为 446 个 Point、EPSG:4326、6 个非几何字段，全部满足 CA 条件，无重复 ID；SHA-256 和字节数与清单一致 |
| 直接源核对 | 单独请求源服务 ID 清单：446 个，集合与下载文件相同；仅证明该次核对的 ID 一致 |
| 重载后复跑 | 已成功复跑一次；修复后表单与保存查询一致。另有请求因源服务读取超时或 SSL EOF 失败，界面保持失败，不显示旧成果为成功 |
| 部分/未知/失败 | 定向测试覆盖缺失/重复 ID、批次失败、源 ID 改变、无法安全判断、无产物 unknown、网络失败及 UI 状态。没有在真实公共服务上人为制造 partial/unknown |
| 前端 | `node --test frontend/tests/connector_online_load.test.cjs frontend/tests/workspace_dock_state.test.cjs`：15 项通过 |
| 后端 | 仓库 `.venv` 执行 `test_url_gis.py`、`test_url_vector_jobs.py`、`test_mcp_server.py`：42 项通过，1 条 Pydantic Settings 的 lifespan 前向引用警告 |
| STDIO | 真实 Python 子进程测试在 GBK 默认控制台编码下完成握手、8 个 MCP 入口发现和完整 GIS 目录读取；不是逐一验收所有外部客户端 |

失败已作为修复依据保留：旧环境最初在测试收集时失败；旧 STDIO 曾出现解码错误及目录读取超时；旧 JSON 下载没有落盘。上述项已针对性修复并复测。外部服务超时/SSL 错误仍可能发生。

**计时边界：** 本轮复用了已有环境，没有干净机器安装耗时。浏览器分段观察时长含工具和其他检查间隔，原始值保存在 JSON 的 `agent_observation_elapsed_ms_not_benchmark`，不能当成陌生用户操作时长或速度优势。未完成连续的真人首用计时；“几分钟内独立完成”尚未证实。没有运行全仓库测试。

## E. 下一项最小真人验证

招募 5 名近一个月实际从公开 REST 服务取过矢量数据的学生或分析人员。优先使用他们自己真实、公开且可访问的 URL；没有真实任务的人可做可用性观察，但不计入需求验证。不要先推销 MCP 或“可信交付包”。

1. **准备单独计时：** 记录安装、依赖、启动和准备输入耗时。应用已启动、图层未加载后才开始应用内计时。观察者先记录受试者原有 QGIS/GDD/脚本路径，使用相同查询与验收要求；轮换工具顺序。
2. **给受试者的任务：** “请从你这条公开服务地址获取本次要交接的数据，查看结果，并保存足够让同事检查和再次获取的文件。请判断这份结果能证明什么，以及还有哪些不能证明。”不讲操作步骤。
3. **观察：** 是否找到入口、选择预览/完整、读懂检查结果、取得文件、发现未知项；记录完成率、独立完成、帮助次数、活跃时间、网络等待时间和错误发生点。完成前不给提示；必要帮助单独记录。
4. **理解检查：** 请受试者解释：预览是否等于完整；对象 ID 一致是否等于属性快照一致；示例是否能证明当前人口结论。答案原文和解释发生的时刻要记录，不能用观察者的讲解代替。
5. **错误恢复：** 在另一个可恢复任务中给一个错误图层编号，观察能否识别失败、修正并重试；不破坏源数据。失败/部分/未知也算真实观察结果，不自动记为软件成功。
6. **独立交接与复用：** 同事在 QGIS/GDAL 核对数量、CRS、字段和范围；分别记录是否愿意再用以及 7 天内是否带来第二个真实任务。意愿不是留存证据。

使用 [空白观察表](validation/first-use-observations.csv)记录；文件只有表头，没有虚构参与者。

预设继续门槛：5 人中至少 4 人在应用已启动后 5 分钟内独立拿到并正确解释成果；至少 4 人说清预览/完整和属性快照边界；至少 3 人能从错误编号恢复。比较相同验收的原流程总时间，安装时间另列。7 天内至少 3 人带来第二个真实任务，才扩大投入。这是小样本决策规则，不是市场比例预测。

若多个用户都卡在同一步，先修这一步再复验；若多数人的真实任务不需要这些检查/交接文件、原工具同样方便，或安装成本抵消节省，则停止把此方向作为工作台主打，考虑保留为可复用检查组件。没有达到门槛时，不靠增加分析工具或推广 Star 来替代验证。
