# 项目路线图

更新日期：2026-10-11。以下为按当前仓库盘点制定的工作顺序，不是发布日期承诺。当前未核验正式版本发布，桌面包的 `0.1.0` 元数据不作为仓库版本依据。

证据、清理建议与 GeoLibre 对照见 [仓库盘点](repository-audit.md)；OCS 规则仍需按具体届次确认。

## 第一阶段：让别人克隆后能够复现

- [ ] 补充可分发的最小 GeoJSON 示例，修正忽略规则，并提供不依赖模型和网络的基本分析演示。
- [ ] 在干净环境核对全部直接依赖、安装和启动命令，记录操作系统、Python 版本和提交号。
- [ ] 启动脚本优先使用明确的解释器/当前虚拟环境，移除对开发机安装位置的优先依赖。
- [ ] 建立 CI：先保证无凭据、无外网条件下的确定性检查，再把在线集成测试单列。
- [ ] 统一 README、审计报告、更新日志与展示材料；按运行时数据库显示规模和快照信息。
- [ ] 整理开发日志和历史设计稿的文档导航；个人开发目录与运行缓存不做无依据的批量删除。
- [ ] 为目录快照和内嵌地理边界补来源、许可、更新时间和更新办法。

验收：干净克隆能按说明安装、运行一个本地分析并导出结果；无需访问开发者的其他仓库或私人配置。

## 第二阶段：把数据获取做成可靠主流程

- [ ] 为来源区分可下载、仅在线展示、仅目录、需认证、人工指引与不可用。
- [ ] 按 AOI、时间、数据类型、CRS、许可和访问条件检索与筛选。
- [ ] 选择一个明确场景、少量稳定来源，验证搜索 → 确认 → 获取/加载 → 检查 → 分析 → 导出。
- [ ] 明确错误、重试上限、取消和替代方案；不把认证指引算作下载成功。
- [ ] 导出来源、获取时间、输入校验和、工具参数、坐标系/单位与输出清单。
- [ ] 检查手动与 AI 入口的结果一致性、历史重跑和 2D/3D 图层同步。

验收：固定场景可重跑；网络、权限或输入失败可解释；结果能够追溯到来源与执行参数。

## 第三阶段：验证差异并准备参赛版本

- [ ] 用相同任务和条件实测 GeoLibre；对照公开文档和实测结果分别记录。
- [ ] 比较完成率、结果质量、操作步骤、耗时、人工干预和失败恢复，保留原始记录。
- [ ] 确认 OCS 届次、赛道、参赛资格、提交要求和截止时间。
- [ ] 固定提交或发布版本，完成新环境演示，准备截图、视频及按规则要求的其他材料。
- [ ] 明确第三方代码、数据、模型服务、参考设计与团队贡献。

验收：项目陈述与现场演示一致，优势有证据，不以工具数量或未经核验的对方缺失功能作为结论。

## 后续维护

在上述流程稳定后，再按实际需求拆分 `tools.py`、优化大数据渲染与内联地图资源、扩展数据格式或专业工具。移动端、更多渲染引擎和插件市场暂不作为参赛前优先事项。
