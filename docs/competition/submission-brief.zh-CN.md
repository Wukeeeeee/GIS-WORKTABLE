## 一句话介绍

GIS WorkTable 是一个开源 GIS 工作台，将本地空间数据、手动分析工具、AI 辅助编排、地图查看和工程成果放在同一工作区中，支持用户沿着可检查的数据与处理结果继续工作。

## 要解决的问题

轻量 GIS 任务经常需要在文件、桌面 GIS、地图网页和通用 AI 对话之间反复切换。数据对象、坐标参考、分析参数与输出文件容易失去对应关系。GIS WorkTable 试图把数据接入、空间处理、地图检查与成果保存连成一条工作流；AI 是可选的任务入口，手动 GIS 操作不要求配置模型服务。

项目定位为通用 GIS 工作台，不是行业认证系统。空间覆盖或距离结果只表达所选数据、坐标系和计算方法下的空间关系，不替代专业审批或领域判断。

## 方案与可检查的特点

- **AI 与手动工具共用 GIS 能力。** 手动面板提供明确参数；AI 服务可选，负责理解与编排任务。实际成果仍应回到图层、属性或文件检查。
- **中间结果可继续参与工作。** 分析结果进入图层工作区，便于继续查看和保存；当前浏览器验收覆盖缓冲结果保存后随工程恢复。
- **工程成果可恢复。** 项目记录图层和视图状态；栅格工程还涉及预览与原始 GeoTIFF 的保存。相关后台测试覆盖部分栅格持久化和导入导出链路。
- **本地分析可独立于 AI。** 手动工具不要求模型 API Key；在线底图、在线数据源和 AI 调用仍分别受网络、账号、配额及服务条款限制。

这些是实现和工作流特点，不宣称为行业首创，也不代表已证明优于成熟 GIS 产品。创新性和效率优势应通过固定任务与对照数据进一步验证。

## 当前运行证据

2026-10-25 在 Windows 本地服务和 Codex 内置浏览器中，完成了以下人工验收：

1. 新建工程并从内置示例加载多边形图层，地图显示 3 个要素。
2. 对示例执行 500 米缓冲，结果生成 3 个面要素并显示在图层列表。
3. 距离为 0 或格式错误的多环距离被拒绝，失败操作没有创建结果图层。
4. 保存工程、刷新浏览器并重新打开后，样例图层、缓冲结果、COG 栅格及栅格预览仍可访问。
5. 通过在线数据入口加载公开 RGB COG 影像并随工程恢复。

针对空间工具、工程栅格持久化和云原生栅格的定向自动化批次为 139 项通过、4 项 slow 测试排除、1 条警告；另一个公开远程 COG slow 集成用例为 1 项通过、1 条 Rasterio/GDAL Windows 解码警告。上述数据来自分开的测试批次，不是全库测试结论。

## 演示建议

优先演示一条手动、无模型依赖的 GIS 路径：导入小型 GeoJSON → 检查图层类型、字段和 CRS → 运行 500 米缓冲 → 检查结果 → 导入便携 `.giswork` 工程并确认两层数据恢复。该流程已在 Windows 本地工作台和内置浏览器中人工验收；Shapefile、GeoPackage、大型数据文件及全新电脑部署仍未验收。在线数据可作为可选片段：当前公开 ArcGIS REST 服务已实际取回并加载 1,000 个要素的限量预览，但没有核对完整性，且第三方示例服务可能变化。AI 编排也可作为可选片段，需说明所用模型、联网和密钥条件。

## 技术与开源治理

项目使用 FastAPI、LangGraph、Leaflet、CesiumJS 及 Python GIS 依赖。项目代码以根目录的 [MIT License](../../LICENSE) 发布；依赖、底图、在线服务、影像及数据各自遵循适用条款。提交前应固定仓库版本，并核对第三方代码、图标、字体、数据来源和许可证。

大赛赛道一、二当前公布的评分权重为技术创新 30%、场景落地 30%、开源治理 20%、长期发展 20%。因此提交包还需附可运行代码仓库、项目介绍文档和核心功能演示视频；文档应写明部署条件、复现步骤、证据边界、贡献方式及后续维护计划。
