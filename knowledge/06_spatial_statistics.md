# 空间统计

## 适用场景

- 分析空间数据的分布模式（聚集/随机/均匀）
- 识别热点和冷点区域
- 点密度估计和可视化
- 空间自相关分析（属性值是否在空间上聚集）
- 空间回归分析（考虑空间依赖性的建模）
- 插值分析（将点观测扩展为连续表面）
- 用户要求"分析分布规律""找热点""做密度图""空间相关性"

## 输入数据要求

### 点数据（密度/热点/聚类）
- 点图层，要素数建议 > 30（统计显著性需要样本量）
- 可选权重字段（如人口、事件数）
- 坐标为 WGS84 或投影坐标均可（密度计算建议投影）

### 面数据（空间自相关/回归）
- 面图层，每个面有分析属性字段
- 面之间应有邻接关系（共享边界或顶点）
- 属性字段应为数值型，无过多缺失值

### 插值
- 点图层 + 数值字段（待插值变量）
- 点分布应覆盖研究区，避免外推
- 建议 > 10 个采样点

## 分析思路

空间统计与传统统计的核心区别：**空间数据不独立，存在空间依赖性**（Tobler 地理学第一定律： everything is related to everything else, but near things are more related than distant things）。

分析决策流程：
1. **描述性统计**：先看属性的均值、标准差、分布（spatial_field_stats）
2. **空间模式检验**：是聚集、随机还是均匀？（Moran's I）
3. **定位热点**：哪里高值聚集？哪里低值聚集？（Getis-Ord Gi* / LISA）
4. **密度估计**：点事件的空间密度如何？（KDE）
5. **空间建模**：变量之间的空间关系？（空间回归）

## 处理流程

```
1. 数据准备
   ├─ get_layer_detail 确认图层和字段
   ├─ spatial_field_stats 检查属性分布和缺失值
   ├─ 投影到合适坐标系（密度/距离计算）
   └─ 面数据确认邻接关系完整

2. 全局空间自相关（Moran's I）
   ├─ execute_python：pysal/esda 或手动实现
   ├─ 计算 Moran's I 统计量 + z-score + p-value
   ├─ 判断：I>0 聚集，I≈0 随机，I<0 分散
   └─ p<0.05 表示模式显著

3. 局部空间自相关（LISA / 局部 Moran's I）
   ├─ 每个要素计算局部 Moran's I
   ├─ 分类：HH（高-高热点）、LL（低-低冷点）、HL、LH
   └─ 结果作为属性字段加入图层，分级设色显示

4. 热点分析（Getis-Ord Gi*）
   ├─ execute_python：计算每个要素的 Gi* z-score
   ├─ z>1.96 显著热点（高值聚集）
   ├─ z<-1.96 显著冷点（低值聚集）
   └─ 结果符号化显示热点/冷点/不显著

5. 核密度估计（KDE）
   ├─ execute_python：scipy.stats.gaussian_kde 或 sklearn
   ├─ 选择带宽（bandwidth）：Silverman 经验法则或交叉验证
   ├─ 生成规则格网，计算每个格网密度值
   ├─ 输出为栅格（GeoTIFF）或等值线图
   └─ 可视化：plt.imshow + 色带

6. 插值分析
   ├─ spatial_interpolate(layer_name, field, method="idw"/"rbf")
   ├─ IDW：反距离加权，简单快速
   ├─ RBF：径向基函数，更平滑
   └─ 结果为栅格，可叠加显示和提取等值线

7. 结果展示与解释
   ├─ 分级设色显示热点/冷点/密度
   ├─ create_chart 展示属性分布
   ├─ 文字解释：空间模式类型、显著性水平、热点位置
   └─ 指出方法局限性（样本量、边界效应、带宽敏感）
```

## 方法选择依据

### 全局 vs 局部

| 问题 | 方法 | 输出 |
|------|------|------|
| 整体上是聚集还是随机？ | 全局 Moran's I | 一个统计量 + p 值 |
| 具体哪里是热点/冷点？ | 局部 Moran's I (LISA) / Getis-Ord Gi* | 每个要素的分类 |
| 点事件密度如何分布？ | KDE 核密度估计 | 连续密度面 |
| 未知点的值是多少？ | IDW/RBF/克里金插值 | 连续预测面 |

### Moran's I vs Getis-Ord Gi*

- **Moran's I**：检测空间自相关（相似值是否聚集），区分 HH/LL/HL/LH
- **Getis-Ord Gi***：检测热点（高值聚集）和冷点（低值聚集），不考虑高低聚集
- 两者互补：Moran's I 告诉"有没有聚集"，Gi* 告诉"热点在哪"

### 插值方法选择

| 方法 | 特点 | 适用场景 |
|------|------|---------|
| IDW | 简单、快速、精确通过采样点 | 数据点密集、分布均匀 |
| RBF | 平滑、可处理不规则分布 | 中等数据量、需要平滑表面 |
| 克里金 (Kriging) | 有统计理论、给出估计误差 | 数据有空间结构、需要不确定性 |

项目当前支持 IDW 和 RBF；克里金需通过 execute_python 用 scikit-gstat 或 pykrige 实现。

### KDE 带宽选择

- 带宽太小：密度图噪声多、过拟合
- 带宽太大：密度图过度平滑、丢失细节
- 经验法则：Silverman bandwidth = 1.06 * σ * n^(-1/5)
- 建议：尝试多个带宽，选择能清晰显示模式又不过度噪声的值

## 输出结果

- 空间统计结果通常包含：统计量值、p 值（显著性）、空间分类（HH/LL/HL/LH 或热点/冷点/不显著）
- 结果可作为属性字段加入原图层，用分级设色显示
- KDE 和插值结果为栅格（GeoTIFF）或 PNG 可视化
- Agent 应说明：使用的方法、关键参数、显著性水平、主要发现（热点位置、聚集程度）、方法局限性

## 常见问题

### Q1：Moran's I 的 p 值不显著
- 原因：样本量太小（<30）、数据确实随机分布、空间权重矩阵选择不当
- 解决：增加样本量；尝试不同的空间权重（Queen 邻接 vs K近邻）；检查属性是否有空间变异

### Q2：KDE 结果全是一片均匀颜色
- 原因：带宽太大，过度平滑
- 解决：减小带宽；或数据本身分布均匀（这也是一个发现）

### Q3：插值结果在研究区外有不合理值
- 原因：插值是外推，边界外不可靠
- 解决：用研究区边界 clip_raster 裁剪插值结果；报告中说明仅研究区内可靠

### Q4：热点分析结果和直觉不符
- 原因：使用了原始值而非标准化值，或空间权重范围不当
- 解决：Gi* 计算前应标准化字段（z-score）；调整距离阈值或邻接定义

### Q5：面数据空间自相关分析报错
- 原因：面之间没有邻接关系（岛屿、孤立面），或几何无效
- 解决：topology_check 修复几何；对孤立面用 K近邻权重替代邻接权重

### Q6：create_heatmap 和 KDE 有什么区别
- create_heatmap 是前端 Leaflet.heat 的简单点热力图（基于像素距离），适合快速可视化
- KDE 是统计意义上的核密度估计，有带宽概念和统计解释，适合专业分析
- 专业分析用 KDE（execute_python），快速展示用 create_heatmap
