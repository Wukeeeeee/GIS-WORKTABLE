## Agent 使用指南

### 任务匹配规则

Agent 接到用户请求后，按以下顺序判断需要加载哪些知识模块：

1. **先判断任务类型**：是数据处理、空间分析、遥感、地形、制图还是综合项目？
2. **匹配对应模块**：根据任务类型加载 1-3 个相关模块，不要全部加载（避免上下文溢出）
3. **基础模块兜底**：任何 GIS 任务都可参考 01_gis_basics 的标准处理流程
4. **综合项目用 10_workflows**：用户描述的是一个完整项目（如"选址""评价"）时，优先加载工作流模块

### 知识应用方式

加载知识库后，Agent 应：

1. **任务理解阶段**：用"适用场景"确认任务是否匹配该方法
2. **数据检查阶段**：用"输入数据要求"核对用户数据是否满足条件，不满足时先提示或预处理
3. **方法选择阶段**：用"方法选择依据"在多种方法中做决策，并向用户说明选择理由
4. **工具调用阶段**：用"推荐工具"中的 @tool 名称执行，按"处理流程"的步骤顺序调用
5. **结果解释阶段**：用"输出结果"和"常见问题"解读结果，指出局限性和注意事项

### 多模块组合示例

- "给我做一个城市公园选址分析" → 加载 10_workflows（选址流程）+ 05_spatial_analysis（缓冲区/叠加）+ 06_spatial_statistics（核密度）
- "计算这个区域的 NDVI 并分类" → 加载 07_remote_sensing（NDVI/分类）+ 04_raster_processing（栅格处理）
- "把这些点转成热力图" → 加载 06_spatial_statistics（核密度）+ 09_cartography（可视化）
- "数据上传后帮我检查质量" → 加载 01_gis_basics（数据检查）+ 03_vector_processing（清洗修复）

## 知识库与工具的关系

知识库提供"为什么这么做"和"怎么做才对"的专业判断，工具（backend/services/tools.py 的 85+ 个 @tool）提供"执行能力"。Agent 不应只凭工具描述做决策，而应结合知识库中的方法选择依据和常见问题来避免专业错误。

典型错误示例（知识库可避免）：
- 在 WGS84 经纬度下直接算面积 → 知识库 02 指出必须先投影到等面积投影
- 缓冲区结果是椭圆 → 知识库 05 指出经纬度下做缓冲会变形
- 空间连接结果为空 → 知识库 01 指出应检查 CRS 一致性和 predicate 选择
